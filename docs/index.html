工序 01

数据是什么，我们做了什么

不编数据 · 用真实公开工业数据

① 这份数据是什么？一座真实半导体工厂 2008 年 7–10 月的生产记录（公开数据集 UCI SECOM，任何人可下载核验）。共 1567 个生产批次，每个批次记录了两样东西：

  • 生产该批次时 590 个传感器的读数——温度、压力、流量这类制程参数（出于保密，传感器只有编号、没有名字）；
  • 该批次最终的质检结果：合格或不合格（1567 个批次里有 104 个不合格）。

② 我们对它做了什么处理？四步，全部可在源码中复核：

原始记录
1567 批 × 590 列→ 剔除无信息列
常量 116 + 缺失过半 28→ 缺失值补齐
剩 446 列 · 中位数插补→ 数据驱动选参数
与不合格最相关的 #59→ 送入监控
SPC 引擎（工序 02）

第 4 步说明：从 446 个传感器里，用统计相关性（哪个读数的波动与"批次不合格"关系最强）选出 #59 作为被监控的关键过程参数——由数据选出，不是人挑的。

③ 凭什么能类比赛力斯产线？把"传感器 #59"换成焊接电流、喷涂流量这类过程参数，把"批次质检结果"换成整车下线检测——监控与诊断的逻辑完全一致。这正是"引擎与领域解耦"的含义：换数据接口与工艺本体即可迁移，引擎不动。

工序 04

影子协同 · 分级放权

自主执行权不是天生的，是用数据挣来的

传统 Agent 做到"检测后提醒人处理"为止。这套系统多走一步：gate 判 A（证据齐、置信够）的处置，一开始也只出建议、仍由人执行（影子期）；系统同时记录 AI 建议与产线实际走向是否一致。某类处置攒够 n≥3 例且一致率 100% 才获得自主执行权；自主执行后一旦复测未恢复，立即收回自主权退回影子期重新累积。放权与收权全部由确定性代码按可复核的统计规则裁决，不由模型自评。

这条阶梯在真实数据上双向走过一遍：该类处置在批次 #166 挣得自主权，连续 3 次自主执行复测均恢复；到批次 #634 一次自主执行后复测未回到受控，自主权当即被收回，退回影子期从零累积。机制会自我纠正，不是单向发放的许可证。

▲ 演进带由工序 03 的事件按时间顺序生成（快照真实数据）：青色 = 影子期（AI 只建议），红色虚线框 = 放权事件，绿色 = 自主执行。

工序 06

换脑对照试验

同数据 · 同 gate · 只换推理大脑
当前大脑：

STUB · 占位（无需 key，本地可复现）

DEEPSEEK · 真模型推理输出

这两个按钮在切什么？整套系统里只有"根因推理的大脑"是可替换的：stub 是不调用任何大模型的确定性占位（保证任何人无 key 也能复现），DeepSeek 是真实大模型的推理输出。切换后，上方工序 02/03 的全部输出（事件裁决、诊断单、来源标记）都会替换为该大脑的结果——可回到工序 03 对照查看。同数据、同 gate，大脑不同 → 根因与裁决不同，证明背后是真模型在推理、真 gate 在兜底，不是写死的文案。

备注：SECOM 为真实半导体制造数据（传感器匿名），用于证明引擎可跑通；规格限由稳定基线派生（CL±6σ）仅供演示；stub 后端基于真实检索确定性产出假设，DeepSeek 快照为真实模型输出；影子放权门槛 n≥3 / 一致率 100% 为演示值（放权门槛参数而非效果承诺），生产环境按质量体系配置（建议 n≥200 / ≥99%）。所有外部数字均有据可查。
